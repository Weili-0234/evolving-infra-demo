Data, playback, and pricing

The first scene replays matched session fd0aecb95d7f. Both arms have 25 model calls, 15,028 output tokens, and matching per-call prompt and output lengths. Cache hit and user cost accumulate over completed calls only. Cache hit is cached input tokens divided by all input tokens. User cost divides all token charges by input plus output tokens and multiplies by one million. Cached input is counted once. Before the first completion both values are undefined. The annotation beside each clock reports the current first-token wait.

Tool-call and between-request intervals have zero screen time. Recorded first-token waits and decode intervals are preserved on a model-serving timeline, including overlapping requests. Both panels use the same playback rate: 8× while either panel streams output, 120× during waits with no output. The model clock excludes the omitted intervals. Original session elapsed times are 31:03 for Dynamo+SGLang and 10:51 for Evolving Infra.

Terminal text is illustrative. Tool commands, filenames, diffs and test results are illustrative too. The source events contain timing and token counts, but no transcript or individual token-arrival timestamps; text reveal is interpolated between first-token and completion events. The sample demonstrates cache reuse alongside measured latency; the runs also differ in allocation and routing, so this is not a cache-only causal ablation.

The default presentation shows curves without tiles. The optional session grid groups state counts: waiting for the first token fills from the bottom, generating sits above it, and tools/between calls appear above that. Counts use a trailing 60-second average of the recorded 10-second samples and interpolate between samples, as a calmer view of concurrent sessions. Tiles represent counts, not fixed session identities. There are no completion flashes. Revenue, cost and cache hit retain the original cumulative measurements without that smoothing.
